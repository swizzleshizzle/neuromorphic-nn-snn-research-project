# EXP-084 GPU Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Value-iteration judge training and the mode-C look-ahead search run on a chosen torch
device, with the CPU path byte-identical, plus the EXP-084 drivers (Gates C, P, E, M, T),
aggregator and desktop chain.

**Architecture:** The judge's device is the device of its parameters. Which random stream the
encoder uses is decided by the generator passed in: a CPU generator gives the exact evaluation
stream (spikes drawn on the CPU, then moved), a device generator gives the fast training stream.
`train_judge` takes `device=` and writes CPU-tensor checkpoints. `JudgeCritic` returns CPU
tensors, so `lookahead.py` needs no change.

**Tech Stack:** Python, PyTorch (CPU 2.13 on the VPS and laptop; ROCm 2.9.1 on the desktop,
exposed as `"cuda"`), snntorch, pytest, PowerShell for the desktop chain.

**Spec:** `docs/superpowers/specs/2026-10-31-exp084-gpu-port-design.md`

## Global Constraints

- The default device is CPU, and on CPU every existing function produces byte-identical results.
- Search and probes always use the exact stream (a CPU `torch.Generator`), on every device.
- TF32 and reduced-precision matmul are disabled on the device:
  `torch.backends.cuda.matmul.allow_tf32 = False`, `torch.backends.cudnn.allow_tf32 = False`,
  `torch.set_float32_matmul_precision("highest")`.
- Checkpoints hold CPU tensors and load with no `map_location`.
- Gate E bar: every one of the 25 cells within **2 solves** of its published count. Gate M: within
  2 of 127. Gate P stop rule: more than **9 of 4,800** first moves disagree. Gate T: EXP-080's
  `gate_t` (threshold 0.1356358024691358).
- No em-dashes in code, docs or commit messages. Plain commit messages, no trailers. Stage
  explicit paths, never `git add -A`. Never weaken a test.
- Work in a worktree under `/root/projects/.wt/`; prefix every python call there with
  `PYTHONPATH=src`. Pass an explicit Bash timeout on every call (default 120 s, ceiling 600 s).
- GPU tests skip unless `torch.cuda.is_available()`; they run on the desktop in the chain's check
  phase.

## Review Focus

1. **Resuming a checkpoint on a different device kind.** A CPU run resumed with `device="cuda"`
   (or the reverse) would restore a generator state into the wrong generator type and silently
   change the stream. Expected: refused before any training. Test in Task 2.
2. **Gate T writing into EXP-075's checkpoint directory.** The encoder is read from EXP-075's
   outputs; a careless `out_dir` would overwrite a tracked judge. Expected: Gate T writes only
   under `experiments/084_gpu_port/outputs`. Test in Task 6.
3. **A CPU run's `state.json` gaining a key.** EXP-083's Gate V compares replayed random state to
   committed `state.json` files. Expected: a CPU run writes exactly the keys it wrote before.
   Test in Task 2.
4. **Gate E's expected counts from the wrong record.** Expected: read from the tracked EXP-083 and
   EXP-082 records, refused if the record's `limit_states` is not None or its `n` is not 200.
   Test in Task 6.
5. **A device judge inside the search crashing on a CPU mask.** Expected: `JudgeCritic` returns
   CPU scores, so `sequence_eligibility`'s CPU mask applies. Test in Task 3 (GPU) plus a CPU
   test that the critic's output is on the CPU.
